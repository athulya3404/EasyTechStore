B. Project Overview
13. Purpose & Rationale The aim of this project, EasyTech (EasyTechStore), is to develop an enterprise-grade, full-stack e-commerce web platform engineered for purchasing electronic gadgets (smartphones, laptops, audio equipment, computer accessories) with intelligent AI assistance and robust transaction integrity. It addresses the real-world problems of high-concurrency race conditions during flash sales that lead to inventory overselling, security vulnerabilities in client-side payment processing, the difficulty customers face when comparing complex multi-dimensional hardware specifications (CPU, RAM, display, battery), and the lack of personalized, context-aware technical product advice. The proposed system provides a centralized platform where customers can browse catalog items with faceted filtering, perform side-by-side technical gadget comparisons, reserve stock with atomic database-level locks, execute secure simulated payments with cryptographic HMAC-SHA256 signature verification, track order lifecycles (Pending, Paid, Shipped, Delivered), and download GST-compliant PDF invoices. Store managers can oversee catalog CRUD operations, perform batch Excel/CSV imports, manage order state transitions, and monitor sales analytics. Additionally, the system incorporates a Retrieval-Augmented Generation (RAG) AI Chatbot powered by ChromaDB vector embeddings and Large Language Models (LLM) to assist shoppers with natural language gadget inquiries, budget filtering, and technical compatibility advice. The expected contribution of this project is to eliminate inventory leakage under concurrent traffic, ensure tamper-proof payment verification, streamline complex hardware evaluation for buyers, and demonstrate a secure, production-ready e-commerce architecture following clean software engineering standards.

Brief description (design, datasets, tools, procedures, evaluation): EasyTech (EasyTechStore) is a web-based e-commerce platform developed using Python (Django Framework), Django REST Framework, HTML5, CSS3, Bootstrap 5, JavaScript, Redis, and PostgreSQL for database management. The system automates electronic gadget discovery, inventory reservation, cryptographic payment validation, order fulfillment, and AI-driven customer support through a unified portal for customers and store managers. Customers can explore products with faceted filters (category, brand, price range), compare gadget specifications side by side, manage shopping carts with real-time stock verification, and track order lifecycles with automated ReportLab PDF invoice generation. Store managers can manage inventory, process batch catalog updates via Excel/CSV (OpenPyXL), and fulfill orders through a finite state machine. The system incorporates Artificial Intelligence and Retrieval-Augmented Generation (RAG) using ChromaDB vector database and LLMs (Groq / Ollama Llama 3.2 / Qwen) to deliver natural language product recommendations and technical assistance grounded on catalog data. It follows a modular Model–View–Template (MVT) architecture with decoupled domain applications (users, products, category, cart, orders, chatbot) to ensure high maintainability, testability, and scalability. Concurrency controls employ pessimistic row-level locking (select_for_update) and atomic SQL F() expressions to prevent race conditions during checkout, coupled with a 15-minute order reservation expiration worker (cleanup_expired_orders). Two-stage payment processing uses the Strategy/Adapter pattern with HMAC-SHA256 signature verification (hmac.compare_digest) for payment integrity. Evaluation focuses on automated unit and integration tests using Pytest, concurrency load testing verifying zero stock overselling, cryptographic tamper testing, and vector retrieval accuracy across a 1,000-question benchmark dataset.

31. Bias, Fairness & Safety (for AI/ML/NLP/CV)

Expected risks (bias, representational harms, unsafe outputs): The RAG-based AI chatbot may produce hallucinations, out-of-catalog product recommendations, or inaccurate hardware compatibility advice when responding to complex user queries.

Mitigations (sampling, audits, human oversight, content filters, red-teaming): Use Retrieval-Augmented Generation (RAG) strictly grounded on verified store inventory and technical spec sheets stored in the ChromaDB vector database. System prompts enforce explicit guardrails requiring the assistant to decline non-electronics queries and acknowledge when a product or feature is not in the store catalog. Evaluated across 1,000 diverse test questions to verify intent extraction and price-filtering accuracy.

Model reporting (model card/limitations/appropriate use): Document the AI/RAG architecture, vector retrieval parameters, and evaluation benchmark in the project report. The chatbot is designed as an advisory shopping aid and customer support assistant, not an autonomous transactional decision-maker.
